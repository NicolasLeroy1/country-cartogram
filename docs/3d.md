# Two variables: area, height, and volume

Let `A_i` be the first quantity and `B_i` the second quantity. The existing
cartogram gives country `i` a footprint `S_i = k_A A_i`. Extrusion uses

```text
height_i = k_H B_i / A_i
volume_i = S_i height_i = k_A k_H B_i
```

Both `k_A` and `k_H` are global constants. Thus population as `A`, GDP in dollars
as `B`, and GDP per person as height give a map whose volumes are proportional
to GDP. The ratio is **second divided by first**. Supply extensive quantities
for both columns; supplying GDP per capita as `B` would divide by population
again. Convert units before computing ratios: the bundled example converts
Natural Earth's GDP in millions of USD to USD.

## Create a 3D map

Install the optional renderer with `python -m pip install -e '.[3d]'`.
The core 2D package continues to work without Plotly.

```csv
country_code,population,gdp_usd
FRA,60000000,3000000000000
DEU,80000000,4000000000000
ITA,50000000,2000000000000
```

These numbers only illustrate the format. Use a consistent source and year for
analysis. Choose columns explicitly:

```bash
country-cartogram my_data.csv --value-column population --volume-column gdp_usd \
  --config my_2d_config.json --config-3d my_3d_config.json --out output/my_map
```

The configuration files are optional. Normal 2D outputs are produced alongside
the 3D outputs. Add `--preview-3d` for a static orthographic PNG. `--animate`
continues to animate the **2D placement simulation**; it does not animate heights.

Once the first-variable layout exists, change the second variable without
rerunning the simulation:

```bash
country-cartogram-3d output/my_map.layout.json new_data.csv \
  --area-column population --volume-column gdp_usd \
  --config my_3d_config.json --out output/updated_heights
```

The standalone command checks that every positive first-variable quantity
matches the saved layout, including its country coverage and original units.
It also checks that footprint areas are proportional to those quantities.
If population or grouping changes, generate a new 2D layout first. Country
colors are inherited from the companion `.audit.json`, or overridden with
`--style my_2d_config.json`. A standalone layout without an audit uses default
colors. Existing footprints are never repositioned by extrusion.

Python API:

```python
from country_cartogram.extrusion import export_3d

report = export_3d(
    "output/my_map.layout.json", "new_data.csv",
    area_column="population", volume_column="gdp_usd",
    config_path="my_3d_config.json", output="output/updated_heights",
)
print(report["max_relative_volume_error"])
```

## Scale and presentation

Example 3D configuration:

```json
{
  "title": "Population beneath the world economy",
  "area_label": "Population (people)",
  "height_label": "GDP per person (USD)",
  "volume_label": "GDP (USD)",
  "source_note": "Your source, year, and coverage",
  "height_scale": null
}
```

`height_scale: null` chooses a common multiplier so that the highest country
is 25% of the larger horizontal map span. The multiplier is recorded in the
audit. An explicit positive number fixes chart-height units per ratio unit;
for example `0.0002` means a ratio of USD 50,000/person produces height 10.
Use the same explicit height scale **and** area scale for comparisons between
different maps. Automatic normalization is independent for each export.

No logarithmic heights, percentile clipping, individual height normalization,
or minimum nonzero height are applied: each would break the stated volume
encoding. A shared vertical exaggeration preserves relative volumes, and
`height_scale` controls it. The axis displays ratio values, not arbitrary
chart-height units. The initial camera is orthographic. Rotation, zoom, continent
visibility, a top-view button, hover values, and a country table help inspect
countries that other extrusions obscure. Perspective and occlusion can still
make visual volume comparisons difficult; use the numerical values for precision.

## Zeros and missing data

- `A > 0, B = 0`: retain a flat footprint with exactly zero volume.
- `A = 0, B = 0`: omit the footprint and list the code in the audit.
- `A = 0, B > 0`: reject; a finite-height zero-area extrusion cannot encode it.
- Negative, nonfinite, blank, duplicate, or missing quantities: reject.
- A country absent from the paired input must also be absent from the layout.

The historical paired example includes 231 countries / territories. Vatican
City is excluded because the source marks its GDP as missing (`-99`). Pitcairn's
reported zero GDP is retained as a flat footprint. Years vary and both year
columns are retained. These are software demonstration values, not current or
harmonized economic statistics.

## Mesh construction and validation

The exporter extrudes the finer saved polygons, not the collision hulls. A
[constrained Delaunay triangulation](https://shapely.readthedocs.io/en/stable/reference/shapely.constrained_delaunay_triangles.html)
preserves concave coastlines, holes, and separate islands. Roofs, reversed
floors, and oriented side walls form closed meshes for positive heights. A
zero-height country has only its roof. There is no additional outline
simplification in the 3D stage.

Independent checks measure roof triangles, count edges to detect open meshes,
and calculate signed mesh volume by summing tetrahedra. Exports fail if these
checks exceed numerical tolerances or if measured volumes are not proportional
to `B`. The 3D audit does not rerun the 2D all-pairs gap audit; it preserves the
existing footprints exactly. Use an audited pipeline layout as the input.

| Output | Content |
| --- | --- |
| `.3d.html` | Interactive Plotly mesh scene and accessible country table |
| `.3d.png` | Optional static orthographic preview of the same meshes |
| `.3d.metrics.csv` | Quantities, ratios, heights, areas, mesh volumes, errors, mesh counts |
| `.3d.audit.json` | Global scales, source hashes, versions, coverage, errors, timings |

The default HTML embeds Plotly and works offline. `--html-js cdn` makes a smaller
file by loading its versioned JavaScript from the Plotly CDN. Both are produced
locally; data do not need to be uploaded to a visualization service. A browser
with WebGL support is required. See [Plotly HTML export](https://plotly.com/python/interactive-html-export/)
and [explicit triangle meshes](https://plotly.com/python/3d-mesh/).

## Performance

The expensive country-placement simulation runs only when first-variable values
change. The standalone exporter loads saved polygons and does no physics,
projection, or all-pairs collision search. It uses compiled GEOS triangulation,
array operations for orientation and mesh checks, indexed vertices instead of
duplicating triangle coordinates, and Plotly's typed-array serialization.
The static Matplotlib renderer is imported only when a PNG is requested.

Observed on the development machine, Python 3.12, for the paired world example:

| Measurement | Result |
| --- | ---: |
| Countries / territories | 231 |
| Indexed vertices | 93,398 |
| Triangles | 184,062 |
| 3D export median, three runs | 1.88 seconds |
| Compact HTML size | 4.85 MB |
| Maximum relative volume error | 8.57e-14 |

Timing covers loading, meshing, numerical audits, and compact HTML generation
from an existing layout. It excludes Python interpreter startup, 2D placement,
optional PNG rendering, and browser rendering. The initial implementation took
4.79 seconds median for the same export before vectorizing triangle/edge work.
These measurements are not a hardware-independent guarantee or a browser frame
rate benchmark. Exact runs and dependency versions are in
[the benchmark record](gallery/population-gdp.benchmark.json).

Reproduce the benchmark after generating the paired example:

```bash
python scripts/benchmark_3d.py output/population-gdp.layout.json examples/population-gdp.csv \
  --area-column population --volume-column gdp_usd \
  --config examples/population-gdp.3d.json --out output/benchmark --repeats 3
```

Large custom boundary files can require more memory and slower browser rotation.
Use the existing coastline simplification controls when generating the 2D layout;
doing so keeps the same simplified footprints across both renderers.
